## 实现内容

### 策略页面与编辑

- 策略页改为“服务分配｜策略组”两个标签。两侧搜索、列表和滚动状态各自保留；沿用原生 Qt/QML、现有 Theme、SwirlMotion、菜单、关联弹窗及详情动效。
- 默认策略固定为 `policy:default`，始终置于服务分配顶部，不可删除或停用。默认目标只接受节点、策略组或未配置草稿；界面不提供 DIRECT/REJECT，Rust 同时校验默认组的可达出口，禁止通过嵌套隐藏直连或拒绝出口。
- 自定义服务使用稳定 UUID，可添加多条“仅此域名／包含子域名”，选择节点、策略组或 DIRECT，编辑名称、启用状态和同层优先级。多域名按 OR 匹配，点边界由 Rust 校验；显示名不作为引用身份。
- 冲突提示读取 Rust 校验结果中的双方策略、见证域名和实际优先胜者。部分重叠必须审阅同一候选后保存；修改候选或保存基线后重新审阅。完全重复且出口不同、循环和无效引用由 Rust 拒绝。不会隐式认定更具体域名优先。
- 策略组支持手动选择、自动测速、故障转移、负载均衡及嵌套。手动选中项显式保存，删除候选不会自动改选第一项。高级探测参数折叠显示，保留 URL、间隔、超时、状态码、容差、成功/失败阈值、切换冷却及既有 TLS 参数。
- 出口选择器读取真实目录和策略组，不填充示例节点；不可用目标保留说明。默认策略、服务策略和手动组成员使用同一选择器，但按各自能力限制可选项。
- 对话框等待自己的 `request_id` 和匹配的持久化/运行回执后才关闭。失败保留草稿；在途操作阻止再次提交和 Esc 关闭。成员、域名等非文本修改也参与未保存检测；长表单支持键盘焦点滚入可见范围。
- 保留策略页连接、断开和代理端口入口。当前策略页的模式选择通过真实事务生效后更新；活动页的正式模式控件仍属阶段 6。节点页继续只管理资源，不因浏览、收藏、详情或单节点测速改变出口。
- 离线端口修改也参与配置事务，保存的监听参数与 Rust 计划摘要一致，重开后恢复同一参数；不通过修改内存端口绕过保存回执。首次连接发布内核实际运行回执，轮询仅在相同 epoch/generation/版本/摘要下保留已确认请求身份，不把无请求 ID 的遥测当作新提交确认。
- 服务和组菜单显式采用 Qt 场景内弹出方式，动态菜单项用 Instantiator 加入 Menu，并按字体测量提供非零宽度；保留原样式和动画。实现参照 [Qt 官方动态菜单与 popupType 说明](https://doc.qt.io/qt-6/qml-qtquick-controls-menu.html#dynamically-generating-menu-items)，没有复制第三方产品代码。
- 订阅页仅做必要兼容适配：保存/删除等待匹配的 V2 回执，新增来源 ID 在提交后确认，失败保留输入；明确只自动更新节点。提交期间遇到 reconciling 时，相关弹窗内可直接调用既有恢复流程。完整订阅管理重构仍属阶段 5。
- TUN 与应用进程匹配仍明确不可用。服务表单仅启用网站域名匹配，不把无法识别的应用条件静默降级为域名条件。

### 五层路由与配置事务

schema-1 顺序规则继续保留。旧配置须在策略页查看迁移说明并确认后进入 schema-2；名称歧义、无效目标或不支持规则阻止整份迁移，不部分覆盖。旧 MATCH 指向 DIRECT/REJECT 时保留为明确终结自定义规则，不伪造为默认代理目标。

规则模式由 Rust 按以下顺序计算，QML 不模拟路由：

1. 必要本地网络和显式直连规则；
2. 用户启用的专属服务策略；
3. 中国大陆域名/IP 规则库；
4. 其他自定义规则；
5. 永存默认策略。

全局模式使用默认代理出口并保留必要本地例外；直连模式不经过代理。中国 IP 分类仅在策略明确配置分类 DNS 路径时发起解析；关闭或解析不可得时保留实际分类状态，继续按后续规则处理，不用节点地区或显示名猜测目的归属。

- `PolicyDocumentV2` 使用 `schema:2`、`service_policies`、`groups`、`explicit_direct_rules`、`custom_rules` 和 `missing_targets`；目标为带类型的 node/group/direct/reject/unconfigured。组类型 wire 值为 `manual/url_test/fallback/load_balance`，不是旧版 select。
- C ABI 保留原有所有权和精确 build/source 配对，增加 schema-2 的 validate、start、prepare、activate、finish、rollback、status。旧 mutation 不能绕过 V2 revision/CAS；未知字段、重复 JSON 键、非规范版本及超限均拒绝。
- Controller 只允许一个配置写事务。在线流程先纯校验/准备，再加密写入 intent、关闭新请求准入、激活候选、最终原子提交、执行 finish 后放行。普通切换保留已建立连接的旧快照；中途不确定状态显示 reconciling，不提前报成功。
- 离线保存的回执 scope 为 `saved-next-connect`，不含已应用版本；在线成功 scope 为 `new-requests-applied`，绑定请求、保存版本、实际运行 epoch/generation 和已应用模式。布尔返回值仅表示受理，不能证明实际生效。
- NodeStore 的 V2 加密文件保存 committed 权威状态、单个 pending intent 和版本高水位。QSaveFile 原子写入和路径级 QLockFile 防止旁路写与第二写入者；旧目录同步写入 API 在 V2 下拒绝绕过事务。共享 JSON 原文只在加密 envelope 外层 documents 表保留一份。
- 获得路径锁后复核读取时的密文摘要，过期窗口不能迁移或覆盖其他写入者的新配置；异步工作持有路径锁直到原子写入返回。高水位禁止复用已落盘的版本；纯准备失败且尚未落盘的数字可在重启后重复，但请求 UUID 和运行 epoch 不同。
- 普通明文 HTTP 每个连接仅处理一个逻辑请求，按有界 Content-Length、chunked 和 HEAD 边界转发，响应改为 Connection: close，后续流水线内容不能借旧快照继续转发。CONNECT 保持隧道语义；WebSocket 仅在有界校验实际 101 响应及匹配 Sec-WebSocket-Accept 后转为长流，拒绝升级的普通响应不放行后续内容。这不表示支持持久明文 HTTP 代理连接。

### 目录更新与撤销

- 自动订阅更新强制复用 nodes-only 安全边界，包括旧 full-profile 记录；只管理来源节点，不自动覆盖 Swirl DNS、规则、策略组和默认策略。来源定义改变、删除或下载响应过期时丢弃旧响应；目录基线改变须重新准备/验证，不能提交旧 ImportPlan。lastSuccess 只在完整成功提交后更新。
- V2 新增、编辑、删除节点和来源均走同一目录/配置事务。节点页适配异步完成，不在 accepted 后清空凭据或关闭表单，不把已经从目录移除的节点凭据缓存回详情。
- 删除相关节点保留无凭据 missing-target tombstone；默认出口失效时拒绝相关流量，不改为 DIRECT。成功撤销须完成相关连接、拨号、探测和池的撤销约束后才发成功回执；普通模式切换与凭据撤销的会话语义不同。
- 持久化撤销 intent 后发生崩溃或无法确认结果时，不用旧凭据自动重连。策略页提供“恢复已保存的操作”；恢复校验保留候选及摘要、完成离线提交后仍须用户手动连接。恢复状态可以占有事务 lease，不能仅凭 policyBusy 为 false 推断可编辑。
- 恢复前阻止独立节点测速和旧来源下载；定时更新、手动刷新及 URL 下载均检查配置库可用状态。待处理目录的操作类型、候选快照、网络配置和实际撤销 UUID 集合必须一致，损坏元数据不会被当作普通目录更新自动清除。
- 删除不同 JSON 出站时，剩余节点的源文档仅保留其对应出站，并复核 nativeOutbound 等价；删除整个来源清理保留档案与无用源文档。

### 实际连接解释

Rust 的连接观测经 Bridge/Telemetry 白名单转换为 `record.route`。详情展示真实 rule_id/tier、service_policy_id、group_chain、leaf_node_id/source_id、chosen_ip、DNS 路径/配置、分类/拒绝/出口保持原因以及 revision/generation；节点和组的名称由稳定 ID 查当前公开目录。

自动嵌套组的出口可依服务和上层条件而变，界面不编造一个全局“当前节点”。缺失观测显示“未提供”，不从配置预测实际命中；不展示 plan digest、原始配置或私有源内容。配置版本变化会使旧出口 IP/探测信息失效。

## 已知限制与不能扩大宣称的内容

- **共享单个 JSON 出站的多个账户暂不能安全单独撤销。** 该操作明确失败，目录、文件和运行配置不应部分变化；可删除整个来源，或先按独立出站重新导入。不可通过保留含已删账户的共享原文假装完成删除。
- 一次性完整配置预览/ReviewTicket 和完整订阅管理页面仍属阶段 5。自动刷新现在只有节点授权，不存在永久 full-profile 授权或可重放确认票据。
- TUN、可靠应用进程识别及应用+网站组合尚未支持；不能用空接口或 UI 文案宣称能力可用。
- 当前服务通过明确域名集合配置；真实供应商的域名覆盖、账号与地区条件仍需实际服务验收。受控源站的 A/B 路由证据不能证明 OpenAI、Claude、Google、私人供应商节点或 Codex 登录/聊天可用。
- 普通明文 HTTP 不支持在同一 socket 上复用多个逻辑请求；客户端应按响应的 Connection: close 建立新连接。CONNECT 中的 HTTPS 请求仍属于原有不透明隧道，不对网页解密或迁移已建立流。
- 未重新下载私人订阅，未修改本机代理、TUN、路由、DNS或现有安装。系统接管/恢复只可在获准的可丢弃环境验证；本机正在使用的工作代理不能当作测试对象。
- Windows 最终安装包、源码身份和摘要以交付报告为准，版本设置本身不是打包完成。私人供应商/Codex 成功、完整 DPI/多显示器、实际显示器稳定 60FPS 和长时稳定性仍未验收。
