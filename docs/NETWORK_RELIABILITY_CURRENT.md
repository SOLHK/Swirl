# 当前 Rust 产品的连接可靠性与验收边界

当前网络运行时为进程内的 **Swirl Rust Core**。Qt 通过 `ThreadedEngine`、`RustCoreEngine` 与配套 C ABI 控制运行时；不提供外部兼容内核的选择、下载或回退入口。Clash 等配置导入属于数据兼容，不能据此推断相关协议参数已经获得执行或真实联网验收。

## 使用与诊断

- 从[当前内核说明](../core/README.md)核对协议与能力边界，从[架构说明](ARCHITECTURE.md)核对各层职责。能力校验拒绝的配置不能通过切换外部引擎绕过。
- 系统代理需要明确操作后启用，归属与恢复由现有系统代理会话及守护处理。其他应用是否读取系统代理或进程环境变量，需要核查实际连接路径；不能仅凭界面运行状态判断。
- 连接诊断应区分本机监听、代理握手、TLS 验证、HTTP 响应与长连接生命周期。TCP FIN、超时或某一个 HTTP 状态不足以证明故障属于远端节点、目标服务或本地内核。
- 涉及用户订阅、凭据、节点地址及诊断数据的取证应留在本地并脱敏。不得为检查连接而擅自改动当前代理、路由、DNS 或证书信任。
- 本机 HTTP/HTTPS 工具的实际边界见[捕获说明](../src/Swirl.Quick/CAPTURE.md)。设置和配置草稿不代表 TUN、LAN 或网关数据平面已可用。

## 验收证据

每份验证记录只适用于其中明确写出的源码提交、工具链和测试环境。隔离回环测试、独立协议互通、公开网络请求、私有节点和 Codex Desktop 长连接是不同层次的证据，不能互相替代。当前构建及发布状态以对应提交的 CI 和交付清单为准，不能沿用旧文档的通过结论。

[6A 诊断记录](NETWORK_RELIABILITY_6A.md)与[Codex 登录记录](CODEX_LOGIN_WINDOWS.md)保留各自当时的环境和结果，用于追溯，不构成当前桌面会话已验收的声明。
