## 来源管理界面

- 将订阅大卡片改为一个可复用的紧凑来源列表，顶部提供来源/节点数量、添加、更新全部、名称搜索和全部/失败/自动更新筛选。来源行展示名称、所属节点数、最近成功时间和真实更新状态；更新失败保留上次有效节点。
- 每行支持独立更新、取消下载/排队、更多菜单和按需展开详情。展开区提供更新周期、下一次时间、导入边界说明，以及查看节点、编辑、删除和完整配置审阅入口；没有常驻右侧面板。地址及凭据不进入公开来源行或 QML。
- 新的 `SubscriptionDialog` 优先展示名称、隐藏输入的 HTTPS 地址和自动更新。客户端格式放入高级设置，下载后仍按实际内容检测。没有“完整配置/仅节点”永久授权选项。编辑时空地址保留加密地址，失败保留草稿；关闭后清除地址输入。

- 页面保存、删除、清理和本次配置应用继续等待自己的 `request_id` 与匹配的持久化/运行回执。受理返回值不代表应用成功；在途操作阻止重复提交与 Esc 关闭，并保留既有恢复入口。
- 动效使用原有 `SwirlMotion` 与协调器：行展开可反向接续，列表加入/移除带短距离空间变化，复用时清理菜单与呈现状态；系统减少动态效果仍可直接结束到最终状态。实际原生界面/帧率验收由最终运行记录说明，不能由源码或 qmllint 替代。

## 完整配置的信任边界

自动及定时更新始终只有 **nodes-only** 权限，沿用阶段 4 的单配置事务、稳定来源/节点身份、DPAPI、QSaveFile 和撤销流程。来源携带的 DNS、规则、组、脚本、重写、MITM、监听、TUN 等不会因下载或刷新自动启用。

本阶段在加密的来源导入结果中记录配置格式和**原始响应字节的 SHA-256**；哈希在解码前计算，因此相同逻辑内容的原文和 Base64 响应身份不同。非节点配置仍是有界的加密惰性数据，预览不发起网络请求、不执行脚本、不读取配置声明的本地文件或外部提供者。

用户在来源行主动选择“审阅完整配置”后，Controller 才读取该来源的本机缓存，调用现有 Rust 严格投影和 V2 纯验证，构造不可变候选。节点名只在该来源内按原始别名解析为既有 UUID，不因显示重命名引用其他来源。重复名、未知引用、保留名称冲突、循环、不支持能力或非法参数均拒绝整份候选，不部分应用。

`ConfigurationReviewDialog` 展示 DNS、默认出口、专属服务、策略组、显式直连和其他自定义规则的替换概要及影响。完整应用会替换这些路由配置；现有节点来源、监听参数、模式和系统接管设置不随之改变。导入规则在 V2 的“其他自定义”层保持来源顺序，仍受本地直连、专属服务、中国规则、其他规则、默认策略的五层顺序约束，审阅明确说明这一点。普通已建立连接保留旧快照。

确认票据仅驻留当前 Controller 内存，最多一个，使用单调时钟限制 **10 分钟**，绑定：

- 来源 UUID 与来源定义摘要（含加密地址对应的定义，但不向 QML 暴露地址）；
- 原始响应字节摘要与加密缓存内容摘要；
- 当前配置库 UUID、已保存 revision、V2 候选与 Rust `plan_digest`；
- 当前 UI/Controller 会话身份及当前已加载内核对 schema-2 候选的严格验证结果。

点击“本次应用”即消耗票据；版本、来源、缓存、规则资源或候选身份变化时必须重新审阅。保存通知会立即清理旧票据及其私有工作副本，公开摘要改为失效提示。应用前再次纯验证，异步 prepare/validate 回执的摘要也必须与审阅一致，随后才允许原有配置事务写 intent/激活/最终提交/finish。失败后的新尝试没有重放权限；明确重新审阅后才能发起新请求。保存的 `lastExplicitApplication` 只是惰性审计元数据，自动刷新从不将其作为授权。

离线成功表示“已保存，下次连接应用”；在线成功依赖原有新请求应用回执，不声称旧隧道已经改用新出口。本次审阅不重新导入节点，也不把缓存应用时间写成订阅最近成功下载时间。

### 取消与同步关闭

Controller 先发送 `policyApplyFinished`，再调用导入器完成回调。减少动态效果时，弹窗可能在前一个信号内同步关闭；此时不能丢弃仍在提交的事务，也不能永久留下 `hasPreview` 门禁。本阶段增加 deferred dismissal：提交期间记录关闭意图，完成回调清理公开审阅状态并放行后续来源编辑/更新。聚焦回归实际在同步信号内取消审阅，再保存来源，验证门禁已释放。

## 明确限制

1. **旧缓存没有原始响应字节身份时不能签发票据。** 界面要求由用户手动更新该来源后再审阅，不自动重下载私人订阅。来源本来没有完整配置时只提供节点管理。
2. 完整配置的最终 `MATCH` 为 DIRECT/REJECT 时，与 V2 默认代理图约束不同，当前明确拒绝；不静默转换成代理默认出口。用户可保留节点并在策略页明确设置直连/拒绝规则。
3. 完整来源配置映射沿用严格的现有格式/规则/组能力白名单。脚本、文件、额外监听和其他未映射语义不能执行；旧投影不能安全映射的自动组嵌套、哈希负载均衡等会明确拒绝。策略页本身的 V2 嵌套组能力不等于所有外部配置格式已经无损映射。
4. 共享同一 JSON 出站的多个账户仍受阶段 4 的单独撤销限制；没有因订阅界面重构放宽。
5. TUN、可靠应用进程识别及应用+网站组合匹配仍不可用。真实私人供应商、OpenAI/Claude/Google/Codex 的登录、聊天和路由效果仍未验收；没有重新下载私人来源，没有改动本机工作代理、TUN、路由或 DNS。
6. 0.2.6 仍为诊断交付。实际显示器稳定 60FPS、长时间运行、完整 DPI/多显示器和主观手感未在本文中验收；DPI 人工验收按用户决定进行，不能借此拖延已满足条件的诊断安装包。
