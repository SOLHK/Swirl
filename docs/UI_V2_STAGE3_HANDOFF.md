# UI V2 阶段 3：节点资源库

本阶段版本为 **0.2.4 诊断版**，沿用 `Swirl-ui-v2-20261024` 工作树和同名 work 分支。用户已确认架构并切换后继续开发；不重复请求架构批准。阶段 4–6 仍须实施。

## 已实现

- `NodeSectionModel` 把现有公开目录投影为来源标题及节点虚拟行。手动、订阅 UUID、历史未归属分开；同名来源不合并。空订阅、折叠、组内排序、搜索临时展开及清空恢复保持稳定身份。
- 一个复用 ListView 显示来源与节点。小变更用增量行操作，大重排用一次 layout permutation，持久索引跟随身份。按目录 revision 缓存公开行及来源统计，不缓存凭据，不创建 2000 个常驻控件。
- 单击/键盘移动只聚焦，双击/Enter 打开详情。搜索、筛选、收藏、详情、新增和编辑均不选择/连接出口。隐藏焦点清理，已打开详情单独保留。策略页保留真实出口选择、连接和端口设置；完整双标签策略页属阶段 4。
- 测速菜单提供当前筛选/全部节点；折叠不减少待测集合。按稳定 ID 去重并校验目录，复用有界 Rust 协议探测、取消和独立节点结果。测 B 不会替换正在转发的 A；不把 TCP 握手视为完整代理可用，不把出口耗时写成 RTT。
- 详情只展示该节点自己的测试，避免借用运行出口的成功状态。导入凭据输入依据真实 nodesApplied 成功信号清空，修复依赖中文提示文案导致的残留。
- 表格来源功能默认关闭，其他页旧行为保留。可见保留行用呈现层 Translate 残差接续；池化、身份变化及减少动态效果时归位，保留滚动惯性和已有详情动效。
- 原 SwirlFontBinding 的派生 Binding 在异步字体页创建时报 deferred-parser 警告；改为 QtObject 调度加内层 Binding，保留字体轴计算和延迟节奏。QML 警告仍是测试失败门槛，不屏蔽退出码。

## 验证解释

本地原始证据在忽略目录 `work/stage3-build/`。最终提交、CI 运行、完整计数和包哈希由交付报告记录；不要把本文提交时尚未完成的打包当成通过。

- 现有 NodeViewModelTests，加新 NodeSectionModelTests：模型协议、重复名称/空来源/折叠搜索、持久索引、2000 节点重排、缓存失效及性能。QAbstractItemModelTester 检查模型通知。
- 新增真实受控批量测试：请求 B、重复 B 和不存在 ID，只通过 B 到达 HTTP 服务，配置出口及运行状态不变。既有真实请求、并发、拒绝、取消、HEAD 边界回归保留。
- NodeUiChecks 在独立、从未激活的 Windows 桌面和独立数据目录，运行真实 Qt 窗口、Rust DLL、环回 TCP/HTTPS。验证 A 实际转发期间浏览/收藏/单测 B 后仍经 A，以及策略明确切换 B；保留导入、刷新失败保留、凭据、180 次快速详情、Esc。断言计数、QML 警告和退出码一起判断。
- S4 回归覆盖 100/500/1000/2000 节点、键盘来源折叠、复用、延迟身份、搜索、真实输入/详情、导航及空闲/最小化。隐藏桌面采样不等于实际显示器稳定 60FPS。
- 六次配对采样中，2000 节点投影加排序 P95 从 26.1073ms 降为 15.6766ms；这是模型处理时间，不是帧率。
- 7 项 portable core boundary 通过。原 Verify-S4UiBoundary.py/hash 原样保留；新 Verify-V2UiBoundary.py 仅放行 NodeViewModel 头、上下文菜单、字体 Binding 修复及阶段间策略入口四个精确内容文件。窗口/侧栏仍受原边界保护。
- CI 加入本分支 push 和新模型测试，保留 MSVC、UI_TESTS=OFF、源码/DLL身份、严格网络和清单校验。固定 Actions SHA、只读权限及仅 disposable hosted runner 可修改代理的限制不变。

早期编译失败、凭据输入残留、QML 警告及超时调试日志均保留，修复后以最终重跑为准，不将中途失败改写为通过。

提交前最终本地结果：节点界面 542/0、S4 压力 404/0、最小窗口详情 14/0，进程退出均为 0 且无 QML 警告；分区模型 13/0/0，含 2000 节点/32 同名来源；真实字体轴回归 3/0/0。13 套 CTest 成功，但原生 Qt XML 仍有 11 项跳过（10 项需要独立协议 fixture 环境，1 项需要用户授权私人订阅），未冒称全量协议或私人网络验收。新增有界筛选测试与 5 项真实探测功能场景单独通过、无跳过。最终包的同提交验证仍以 CI 为准。
