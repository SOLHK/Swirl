## 拟议的未来授权条件（待正式纳入有效的新许可证）

**公开分发带图形界面的 Swirl 衍生应用时，必须展示原作者署名。**
无论二改产品是否公开源码、是否改名、是否收费（收费仍需单独取得商业授权），
只要向第三方分发包含受该未来许可证覆盖的 Swirl 材料的带图形界面应用，
分发者必须在应用内可访问的「关于 / About」页面，清晰、持久、可读地显示：

```text
Based on Swirl
Original Author: SOLHK
Original Project: https://github.com/SOLHK/Swirl
Copyright (c) 2026 SOLHK
```

- 允许额外显示衍生作品作者、版本、修改说明或新品牌，但不得删除、误导性改写、
  遮挡、隐藏、伪装以上原项目署名，也不得暗示衍生作品由 SOLHK 官方背书。
- 「关于」页面必须能从主界面或设置中通过正常导航找到；不得仅在 README、
  GitHub 仓库、许可文本、安装目录、外部网页或启动日志中显示来替代软件内展示。
- 不含图形界面的库、命令行程序、后台服务不能机械要求实现 GUI；
  应在可用的 `--about` / `--version` / 帮助信息或同等用户可访问入口中展示，
  并履行许可证所要求的随软件提供通知义务。该例外须在最终新许可证中明确。
- 该 UI 条款是**额外拟议条件**；即使未来纳入有效许可证，也不能替代
  PolyForm 旧版授权以及 Qt、Rust 库、规则数据、字体等第三方材料的独立许可义务。
- 适用时点、覆盖材料、有效授权主体、法定例外、既有许可和修订方式
  必须由最终正式许可证和有效商业合同约定，不能靠本文件追溯处理。

## 当前实际许可状态

- `LICENSE` 只规定分发时传递许可条款或其网址，以及适用的 `Required Notice:` 原文；
  **没有要求二改软件必须在「关于」页面显示该声明**。
- `NOTICE` 包含 `Required Notice: Copyright (c) 2026 SOLHK.` 和
  `Required Notice: Original project: Swirl (https://github.com/SOLHK/Swirl).`，
  应继续按现行许可证传递。

  不受本拟议文件减损。新条款不追溯撤销已合法取得的旧版本许可。

  `docs/LICENSE_COMPLIANCE_REVIEW.md` 所列未决问题。

## Swirl 官方应用示范与验收

官方 Swirl 的 `src/Swirl.Quick/qml/pages/SettingsAboutPane.qml`
新增原作者、原项目及版权可见字段，作为拟议 UI 规范的实现示范。
这项 UI 改动**本身不使第三方受新许可证拘束**。

验收应至少确认：

1. 「设置 → 关于 Swirl」可达，原作者为 SOLHK，原项目链接文本完整，
   版权文案可读；窗口缩放与浅色/深色下不被裁剪。
2. 不因版本字段、主题、语言或网络状态切换而移除署名。
3. 发布安装包同时包含并符合现行 `LICENSE`、`NOTICE` 和第三方通知；
   单纯 UI 出现文字不代表发行包合规。
4. 若计划正式强制下游履行此条款，须另行制定并审阅下一版本的有效许可证，
   明确施行版本和日期、版权/贡献者再许可权限、历史权利和与商业合同的关系，
   再通过受保护的 `test → main` 发布流程。不能直接篡改 PolyForm 官方原文
   或仅修改 `NOTICE` 假装现行协议已有 UI 条款。
