# Variable font stage (2026-10-18)

Swirl's existing font settings now enumerate OpenType axes through Qt 6.9+ QFontInfo, including custom/hidden axes such as HGHT. Import stages a preview, sliders and numeric values update QML font.variableAxes, and Apply saves the confirmed profile and updates all Theme text bindings. A separate automatically saved draft survives restart. Static TTF/OTF and TTC families continue to work. No font transformation, static instancing, metric rewriting, or change to the default rendering engine is involved.

Metadata is cached by family (bounded to 64); slider positions do not allocate an application-owned font cache or re-register font files. Duplicate imports reuse the existing registration. Window/page structure and animation code remain unchanged. Configured axis coordinates apply exactly to the selected family throughout the UI; existing pixel-size hierarchy remains intact.

Local validation on Windows 11 / Qt 6.10.3: five regional TTC families, three axes, direct glyph raster differences, QML live HGHT, fractional numeric input, explicit Apply, independent-process restoration of confirmed and draft values, repeated-import preservation, and selected-font text bindings on overview/proxies/capture. Local-only tests require SWIRL_TEST_TTC and do not upload or redistribute fonts. The opt-in --font-ui-test runs within the existing isolated preview mode.

The active display mode reports 2560x1600 at 150% and 120 Hz. Read-only EnumDisplaySettingsW also lists 2560x1600 at 240 Hz; 120 Hz is the active value, not the panel maximum. The reason for the current mode is not established. No refresh-rate setting was changed. The implementation has no fixed 120 Hz frame cap, but measured frame intervals exceed the 4.17 ms budget in some updates; physical 240 Hz acceptance is pending. Native Qt window captures cover 9/10/11/12/13/14/16 pt and 15 default/boundary/corner configurations. Each separate FreeType/native DirectWrite comparison also covers 945 QImage simulated-DPI cases (five DPRs x seven sizes x 27 axis combinations); these are not system-scale changes. All tested axis-boundary line heights were stable. The 1,440-update same-coordinate stress test retained its page and reached a memory plateau around 500 MiB, after substantial initial cache growth; this is not a bound for every possible coordinate or a claim of constant 120 fps.

Font outlines, metrics, glyph coverage and interpolation tables were not edited. There is no modified font offered as an improvement without visual evidence. Physical-screen clarity, actual Windows scale switching and cross-monitor migration remain untested. The current session lacks a callable native computer-use API; raw Qt test output is not a physical-screen or ToDesk quality proof. No system font installation, registry/display changes, installed Swirl replacement, or proxy changes were made.

Focused existing CTest gate: swirl-font-selection and swirl-all-pages passed (2/2). Local final FreeType font suite passed 8/8; native DirectWrite live-axis/restoration/point-size check passed 4/4. The isolated font UI harness passed all checks, including exact current-family axis propagation on three pages.

Follow-up: input-field and overlay-dialog axis checks added. Cold-load private-memory checkpoints separate manager construction/import from UI/cache growth, but do not attribute allocations to individual font tables or prove leak absence. A frame-coalesced preview experiment did not reduce steady-state memory reliably and worsened frame intervals; it was discarded. Only redundant empty-error notifications were eliminated. Existing direct native-axis updates remain. 240 Hz physical rendering, long-duration distinct-coordinate cache behavior, and final user clarity preference remain open acceptance items.

Final local UI harness: 31 checks passed, including 3 input fields and 2 dialog text items. Direct-update repeated-drag private memory: 228.55 MiB before drag, 433.38 MiB after the first pass, then 485.66/498.84/501.77/501.39/503.10/503.65/501.50 MiB. Median frame interval 8.73 ms, p95 28.19 ms in this 120 Hz test run. These are process-private measurements, not a font-table/GPU allocator breakdown or proof of leak absence. The 4.17 ms physical 240 Hz target is not validated.

`--font-review --preview-preserve-settings --preview-page=fonts` opens an isolated review session using the existing preview infrastructure. Set `SWIRL_TEST_ROOT` to an existing private test directory and provide `--preview-font-file=<local path>`. This mode stages the import for confirmation, retains its fonts/settings within that test root and does not replace the installed app. An optional `--capture-preview=<png>` validates startup and exits automatically. The user-run local launcher and registry/restore plans stay outside Git with all font files and captures.

Review follow-up: duplicate imports now preserve the selected family and unsaved coordinates when that family belongs to the same collection. A dedicated previewAxesChanged notification refreshes QML after registration changes metadata under the same family name; coordinates are normalized against the refreshed range. Synthetic static/variable/range fixtures reproduce both metadata transitions without redistributing user fonts (generate_font_metadata_fixtures.py, FontTools required locally). Simultaneously registered files with identical family names remain ambiguous at the Qt family-selection layer; the regression explicitly removes the prior registration.

Import now checks SFNT/TTC directory and fvar record bounds before engine registration. Focused tests reject truncated TTC, missing variation records, out-of-file offsets and files above 128 MiB while preserving active/draft state and creating no saved import. This is a structural guard, not a complete font sanitizer. Nine final local font checks passed including metadata and duplicate-import regressions.

A new finite distinct-coordinate stress exposes an unresolved issue: after the repeated set stabilized near 498 MiB, 320 new fractional triples raised process private memory to 1229.86 MiB; reset plus 3 seconds idle left 1237.88 MiB. The harness stopped at its 1 GiB safety threshold and correctly failed this check; other UI checks passed. This result supersedes any interpretation of the repeated-set plateau as sustained-coordinate acceptance. The exact owner of retained allocations is not yet measured. Investigation continues; do not ship this as proof of bounded memory or 240 fps.

Local font-body experiment (files remain outside Git): adding only gasp v1 flags 0x000A left every preexisting table byte-identical, excluding the head checksum adjustment field. Under the existing FreeType path all 945 matrix hashes and 50 saved PNGs were unchanged. The native Windows engine changed some rasters, but no physical clarity benefit is established. The original remains the recommended local input; the experiment is not an optimized release. A noncanonical avar wght endpoint was recorded but not changed, since that would alter interpolation.
