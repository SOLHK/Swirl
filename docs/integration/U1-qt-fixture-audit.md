# U1 Windows Qt fixture coverage

The source audit uses integrated base `748040cb84f4a71d79a99cc50ab3807f828b6351`.
The final acceptance result must come from the workflow run at the final
integration SHA; this document and the offline collector tests are not evidence

## Gap and implementation

`src/Swirl.Quick/tests/RustCoreTests.cpp` contains nine distinct fixture-dependent
test slots (eleven `QSKIP` statements, including two additional platform guards).
A normal CTest invocation without a peer cannot validate these slots. The old
`rust-core.yml` Windows job provisioned them, but does not trigger for the U1
branch. The U1 product workflow's subscription fixture covers only the first
slot in the following table. Rust command-host tests do not substitute for the
remaining Qt/FFI/DPAPI tests.

The new `u1-qt-fixtures.yml` builds the actual Qt test executable and its paired
Rust DLL at the triggered SHA and runs the existing independent peer harnesses.
`Run-U1QtFixtures.py` adds a second XML output to each real Qt invocation while
preserving the harness's original arguments, environment, deadlines, logs and
peer-traffic assertions. It does not replace the peers or simulate execution.

| Required Qt slot | Existing harness now explicitly executed | Evidence scope |
| --- | --- | --- |
| `subscriptionProductChainAgainstIndependentPeer` | `ProductQtIntegration`; `test_reality_runtime.py --qt` with REALITY, Vision and Chrome profiles | Actual import, DPAPI save/reload, selection, routing, HTTP/verified HTTPS, data and recreation; HTTP/SOCKS5/SS/VLESS plus REALITY profiles |
| `publicRealityProductChainAgainstIndependentPeer` | `Verify-PublicQtReality.py` | Actual Windows Qt and in-process Rust through two locked official Xray peers to public HTTP/HTTPS; public network failures fail the job |
| `realityLifecycleProductChainAgainstIndependentPeer` | Chrome Vision `RealityQtInterop` tests | TLS 1.2, HTTP control, four invalid credential variants, authenticated stream cancellation, reject rules, listener cleanup |
| `socks5UdpThroughIndependentPeer` | `test_socks5_udp.Socks5UdpIntegration.test_qt_imported_socks5_udp_data_path` | Authenticated and unauthenticated SOCKS5 UDP datagrams and actual peer observations |
| `socks4ThroughIndependentPeer` | `test_socks4.Socks4Integration.test_qt_imported_socks4_and_4a_data_path` | Imported SOCKS4/SOCKS4a through the actual Qt facade |
| `webSocketThroughIndependentPeer` | `test_websocket_transport.WebSocketTransportTests.test_qt_vless_websocket_data_path` | Imported VLESS/WebSocket against the independent transport peer |

| `loonShadowsocksThroughIndependentPeer` | Same Shadowsocks harness, second explicit Qt slot | Loon-formatted import through the same native Rust runtime |

The collector requires all nine slots, exactly one passing incident for each
requested slot per invocation, Qt `6.11.3`, zero skipped Qt entries, all five
lifecycle modes, successful original harness outcomes and zero failing Qt
processes. Missing or malformed XML has an unknown skip count and fails; it is
not reported as zero skips. The collector also checks the actual C++ conditional
slot inventory so a new fixture cannot silently escape the explicit menu.

The workflow preserves the existing actual Qt private-inspector DPAPI/redaction
test and the offline public/lifecycle evidence guards. Those guard tests remain
separate from the real product tests above.

## Reproducibility and limits

- Source checkout, `GITHUB_SHA`, `SWIRL_SOURCE_SHA`, paired DLL metadata and
  official peer build identity must match the triggered source commit. The
  report records actual binary hashes, platform, calls, counts and elapsed times.
- Qt uses `6.11.3` with aqt's reviewed upstream directory-layout fix pinned to
  `8c3695d4a4e1ceabf6a74dc6c79681656dc6b74b`; no Qt downgrade is used.
- The peer build reuses `tools/tests/xray_peer/lock.json`: official Xray
  `92ccc939aaf4f8965f369cf0b142e005aeaa11d5`, REALITY
  `83f621788ca88b83179810b12baa7ae518aacb83`, Go `1.27.2`, verified source/module
  identities and reproducible peer binary rebuilds. It is a test fixture, not a
  shipped proxy engine.
- Python's independent TLS/cryptography fixtures use `cryptography==50.0.2`.
- No provider subscription URL, user credential or private server is required.
  Synthetic local credentials are generated by the existing harnesses. Public
  HTTP/HTTPS remains a required test; an unavailable network produces failure.
- GitHub-hosted Windows Server 2022 execution is not Windows 11 physical-device
  acceptance. Reports explicitly retain `physical_windows_verified: false` and
  `provider_credentials_used: false`.
- New offline `test_u1_qt_fixtures.py` tests only validate evidence rejection,
  inventory and preservation of subprocess behavior. Their synthetic XML is
  never accepted as product regression evidence.
