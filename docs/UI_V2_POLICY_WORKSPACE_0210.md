## 页面结构

- 标题区只保留添加与次级设置；两标签与真实路由模式合为紧凑命令行。端口、规则和节点库入口移至按需高级弹窗。策略页没有启动、停止或选择连接节点的按钮。
- 服务分配以默认出口路径条开场，突出目标与真实来源。按 rule/global/direct 分别解释国内规则、默认出口及专属分配的适用范围；global/direct 不假称已保存的专属服务正在参与路由。
- 专属服务按实际域名用途组织列表，每项直接呈现名称、域名、优先级、出口、来源和启停。分类只是浏览方式，实际优先级及 Rust 事务语义不变。没有制造默认 OpenAI/Claude/Google 规则或假运行数据。
- 策略组展示选择方式、候选数量、已配置成员和实际活动出口。实际出口来自当前 applied revision/generation 的有效活动连接；没有证据时显示“等待流量”，不用配置值伪造实时使用节点。所有连接只扫描一次形成映射，不让每个委托重复扫描全量连接。
- 空组态提供手动、测速、故障转移、负载均衡四种真实创建入口，打开对应预选表单，明确选择候选并保存后才产生策略组。支持既有嵌套、循环检查、引用删除保护和高级探测参数。
- 两标签保留各自列表树、搜索及滚动状态，通过既有原生 motion coordinator 做可中断、可反向的短位移和透明度过渡；未选中的树不接受输入，减少动态效果策略保持。

窗口、左侧导航、14dp 轮廓、中性灰白材质和活动页主布局保持。没有常驻右侧详情面板，没有新增 UI 框架。继续使用已有 Hallmark、UI UX Pro Max、Motion、Qt QML/Review skills；app screen 的保留事务/布局重组原则适用于原生 QML，Web CSS 工具不当作 Qt 验收。原截图是淘汰对象，不作为新设计模板。

参考官方 [Loon 策略组手册](https://github.com/Loon0x00/LoonManual/blob/master/docs/cn/policygroup.md) 和 [Clash Verge Rev 分组组织](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/components/proxy/proxy-groups.tsx) 的可观察功能组织，独立实现 Qt 界面，不引入其网页框架或核心。

## 总开关的实际语义

旧活动胶囊并非总开关：关闭时只动系统代理，Core 继续运行；而根据 Windows 全局 enabled 判断关闭会影响其他软件。本轮修正：

1. 活动页显示“开启代理 / 关闭代理”，以 Swirl 的请求意图、ownership、实际运行状态为依据。其他软件的系统代理只是说明状态，不冒充 Swirl 已开启。
2. 开启使用已保存并明确迁移的 V2 策略，启动真实 Rust Core。健康、持久回执与当前配置相符，且 Swirl 本地监听真实可达后，才走既有 Windows 接管路径。
3. 关闭立即清除 intent/restart 标志，取消旧 TCP 检查，只恢复 Swirl owned 的设置，并停止 Core。事务已进入持久阶段时保持原收敛协议，完成或恢复后停机，不破坏磁盘／Core 一致性。
4. 每次探测有独立 generation，快关快开、晚错误或晚 connected 回调不能接管新会话或清掉新意图。开启失败停止本次运行；恢复失败保留 owned/error，允许重试，不虚报已关闭。
5. 概览和设置中的重复系统代理开关改为状态与“前往活动”入口。TUN、捕获、网关等独立能力不被伪装成总开关已支持的功能。

Rust Core 接口与五级路由不变。SystemProxySession 增加明确所有权的 C++ 构造器 Backend 注入；默认 null 完全使用原 WinINET、DPAPI journal 和独立 guard。没有环境变量、QML 或命令行的生产旁路。只在 UI_TESTS 构建的 node/policy 自检入口注入每实例内存后端，模拟外部设置保存／恢复；真实 Rust 启停、监听探测、路由和配置回执仍实际执行。
