# Swirl 默认自动可变字体系统

## 行为与边界

本实现把字体元数据读取、纯轴策略、配置持久化、窗口显示指标与 QML
接入分开。新用户不需要操作可变轴滑块；没有保存过配置的字体默认自动适配。
原有字体家族、字号、设计字重、布局与动画继续由各组件决定。

“自动”指根据字体规范和已知设计意图可靠地选择坐标，不代表已经证明每种
字体在所有屏幕上更清晰。没有经过验证的字体专属优化参数，也没有启用
PingFang 专属 HGHT 公式。历史实际 DPI 和 240 Hz 未通过项仍保留。

## 轴策略

`FontAxisPolicy` 是独立可测试的纯函数。输入是当前字体的实际轴元数据、
Qt 设计字重、原始字号单位、文本角色、窗口逻辑 DPI/DPR，以及对应家族的
手动设置。它不读取文件、查询系统字体、写入设置或访问动画时钟。

| 轴或情况 | 默认自动模式 | 高级手动模式 |
| --- | --- | --- |
| `wght` | Qt 6 的字重值已经使用 OpenType 的 1–1000 语义。直接保留组件请求的值，再限制到该字体的实际范围；不以全局滑块平移或统一加粗。 | 保留旧版精确坐标覆盖，包括用户主动选择的全界面统一 `wght`。 |
| `opsz` | 使用原始 `QFont::pointSizeF()`；像素字号使用 `pixelSize × 72 / window.logicalDpiY`。结果限制在真实轴范围内。没有有效字号时保留默认。 | 使用已保存的手动坐标。 |
| `wdth` | 字体设计默认值，不因文本长度或布局空间挤压字形。 | 允许在真实范围内调整。 |
| `HGHT` | 字体设计默认值；不将其解释为光学尺寸，不强制最大值。 | 保留原滑块和小数输入。 |
| `ital`、`slnt` | 不设置显式坐标，保留 Qt 原有斜体/倾斜样式匹配，避免轴默认值强制取消组件的斜体。 | 可使用该字体提供的真实轴坐标，保持旧版覆盖语义。 |
| 其他有效轴 | 安全默认值。标签、范围和默认值来自字体元数据。 | 只接受该字体实际存在的轴，规范化到范围内。 |
| 静态 TTF/OTF 或字体不含某轴 | 返回空轴集或不设置该轴，正常使用 Qt 字体渲染。 | 不凭空创建轴。 |
| 错误/重复标签、非有限数字、无效范围 | 排除无效或歧义元数据；不向 QFont 写入 NaN、无穷或不可表示的 float。 | 相同元数据检查；非法交互输入不改变模式。 |

辅助、小标签、正文、按钮、导航、列表、输入、卡片数据、页面标题和大标题
通过现有基础组件和 `textRole` 表达。角色不会引入新的字号表或未经验证的
插值系数。400/500/600/700 的设计层级由原组件保持；若某字体只提供较窄
的字重范围，按真实范围约束，不能保证它具备缺失的粗细层级。

未来如需调整 HGHT、GRAD 等字体专属坐标，应先确认具体字体文件/版本、
轴语义和合法实验资源，记录按角色/字号/显示条件的对照证据，再加入有相应
回归测试的策略。家族名称或轴标签相同不构成验证依据。本次没有添加可由
不可信元数据自称“已验证”的动态规则加载器。

规范依据：[Qt 6.10 QFont](https://doc.qt.io/qt-6.10/qfont.html)、
[OpenType opsz](https://learn.microsoft.com/en-us/typography/opentype/spec/dvaraxistag_opsz)。
对应版本源码与成熟实现的审查来源见
[初始架构审查](FONT_AUTOMATION_AUDIT_20261019.md)。

## 确认、预览与旧配置迁移

`FontManager` 保留已应用配置和预览草稿两个状态。切换字体、手动滑块、
数值输入和自动/手动开关先作用于预览；“应用到整个界面”才确认到实际 UI。
草稿延迟 200 ms 保存，退出管理器时刷新未落盘的草稿。

确认配置使用 `Fonts/profiles/<家族名称的 SHA-256>/` 保存家族、模式和
`manualAxes`。切换到另一个家族读取该家族自己的配置，没有配置则自动；
不会继承前一个家族的 HGHT/wdth 范围或数值。返回已确认的家族可恢复其
手动小数值。临时尚未确认的修改仍属于单个预览草稿。

关闭手动模式保留手动值，再开启可继续使用；“恢复全部轴默认值”才重置
这些数值。“恢复已应用配置”丢弃当前预览，“恢复自动选择”回到默认字体
和自动模式，但不删除其他家族的已保存配置。

旧版没有记录坐标究竟是自动填入的默认值还是用户主动修改的值，无法可靠
推断原意。因此首次升级执行 schema 2 迁移：

1. 将原 `family`、`axes`、`previewFamily`、`previewAxes` 原样备份到
   `Fonts/legacyV1`，旧键也保留。
2. 将非空已保存坐标视为手动配置，保留原数值；没有保存坐标则自动。
3. 独立恢复预览家族、模式和坐标，处理已有的本地化家族别名。
4. 使用实际字体元数据校验可用轴和范围，原始备份不受规范化影响。

旧用户要采用自动策略，只需关闭“手动调整”并应用。启动时字体缺失会选择
默认字体，但其存储配置仍在；运行时字体资源消失则保留请求家族并交由既有
fallback 链渲染。设置同步失败会报告错误，未成功确认不会更新已应用状态。

Qt 仍按家族/样式匹配字体。不同文件若声明完全相同的家族/样式，不能保证
同时注册时选中哪一物理字面；本次未添加物理字体文件选择器。现有同名替换
测试明确移除前一次测试注册，不能用来声称所有同名并存情形都已解决。

应用字体注册由 FontManager 管理。其他模块不得直接移除它持有的 Qt
application-font ID；外部移除后 ID 被复用、再重导原文件的情况不在当前
去重保证内。正常生产路径只有管理器负责这些注册，普通系统字体数据库
变化仍会正确使元数据和预览失效。

## QML、显示指标与资源失效

所有受 Swirl 管理的字体轴写入收敛到 `SwirlFontBinding.qml`，经 `Theme`
进入 `FontManager::resolvedAxesForFont`。具体接入路径及系统 UI 的限制见
[全界面覆盖表](FONT_AUTOMATION_QML_COVERAGE.md)。

传给 C++ 的是完整 QFont。Qt 的 QML `pixelSize` 和 `pointSize` getter
会合成另一个单位的正值，不能据此判断组件原本用了哪种单位。C++ 保留的
`-1` 标志可以准确区分；现有像素型 SwirlText 继续使用原像素默认值，未固定
像素的文本控件和预览也可以保持显式点数。

每个窗口共享一个 `FontDisplayContext`，监听屏幕替换、逻辑 DPI 与实际
窗口 DPR。Qt 本身负责逻辑到物理像素的缩放，策略不再乘 DPR；既有
`Theme.uiScale` 的用户界面缩放规则不改。未变化的指标不发送通知。

由于 QFont 所有子属性共用 `fontChanged`，直接在轴值绑定里读取目标的
整个 font 会造成反馈回环。共享 helper 对字体/配置/显示事件排队刷新，
读取完整字体后仅发布变化的坐标集合。写入轴导致的再次通知会得到同值结果，
不重复写回。移动、透明度、主题颜色和纯变换动画不作为策略输入；字号真的
变化时仍更新光学尺寸，不删除或降低动画。

元数据缓存最多 64 个家族，计算结果缓存最多 256 项。字体导入和
`fontDatabaseChanged` 使缓存失效，多个同轮事件合并通知。动画不重复扫描
字体文件。字体导入保留既有结构校验、SHA-256 去重和原字节保存。

`VariableFontPreview` 继续只持有当前原生栅格和纹理。新增字体资源变化
通知，即使 QFont 属性没变也更新已失效的图像；窗口换屏/逻辑 DPI 改变时
更新 QTextLayout 的设备指标。DPR 仍用于栅格分辨率与物理像素对齐，
原来的边界、字形 overhang、纹理过滤、动画与容差 2 均保留。
组件仅在自身输入失效时设置一个 dirty 标记，避免 Qt 对同值屏幕通知强制
polish 时再次光栅化；每次有效资源或字体变化仍会使标记失效。

## 测试与未完成验收

新增纯策略数据测试、真实原创多轴字体的字形变化与 fallback 检查、
自动/手动状态及旧配置迁移、受限缓存、窗口观察者生命周期、真实 QML
组件更新和预览资源失效测试。原创公开测试字体从程序生成，不读取或改写
用户 TTC；私有字体测试保留并明确报告跳过。

Windows 专项使用 Qt 6.10.3 的 MSVC 2022 x64 二进制及匹配编译器，先
构建独立字体测试，再尝试完整应用。它同时记录实际 SHA、编译器版本、
各个 QTest 的通过/失败/跳过和原始构建日志，参见
[Windows CI 合同](FONT_SYSTEM_CI.md)。真实结果以对应提交的运行记录为准。

公开生成字体能证明轴与状态链路有效，不能证明私有字体小字号主观清晰度。
托管 Windows VM 的 D3D11 WARP 检查也不能替代 Windows 11 物理显示器。
以下项目未因本次代码或 CI 自动获得通过：

- 新智能字体提交上的用户私有 TTC 全矩阵及原有每通道像素容差 2 的验收。
- 真实 Windows 125%/200% 系统缩放及历史首次平移问题的独立复验。
- 同一真实窗口的跨屏、混合 DPI 切换和肉眼清晰度。
- 240 Hz 连续真实轴更新达到稳定 240 fps 的性能目标。

历史证据保留在 [实际 DPI](FONT_ACTUAL_DPI_20261018.md)、
[原生纹理](FONT_NATIVE_TEXTURE_20261018.md) 与
[帧率测量](FONT_FRAME_MEASUREMENT_20261018.md)。后续用户原始报告已证实
旧 delta 3 个例属于参考图缺陷，`fcc5937` 修复后的五档模拟 DPR 矩阵
160/160 通过，容差仍为 2；实际 60 Hz/150% 复测的 9/9 阶段检查通过，
但尾部帧间隔仍超出 60 Hz 周期。不能继续把已更正的参考图个例描述为
已证实的生产渲染缺陷，也不能用旧提交的通过替代新智能字体实机验收。
完整来源与范围见 [验证记录](FONT_AUTOMATION_VALIDATION.md)。本阶段不伪造帧率，
不删除测试、不放宽像素容差、不丢弃连续轴更新来换取通过结论。
