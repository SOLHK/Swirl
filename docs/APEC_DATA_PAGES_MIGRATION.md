# Data pages migration — 2026-10-27

Scope: Overview, Processes, Gateway, Connections, Logs and TrafficAnalytics.
Settings files remain owned by the earlier migration and are frozen apart from
the two object-declaration terminators corrected during real qmlcachegen.

## Interaction before visual layout

Processes, Gateway, Connections and Logs already use the verified
SwirlLinkedDetail/SwirlNodeTransfer source-row, target-slot, interruption and
viewport contracts. Those implementations and actual row-selection actions
are retained. No second detail framework or decorative clock was introduced.
Traffic ranking categories now have stationary buttons and a SwirlArcMotion
selection trajectory. Metric heroTargets and motionSurfaces remain intact.

The backend audit found that setTunEnabled(true), setLanEnabled(true) and
setMeteredEnabled(true) immediately refuse unsupported execution. Overview and
Processes now describe those limits and cannot light an unsupported toggle.
An existing active setting can still be turned off; configuration and allowlist
storage actions are retained. WireGuard/EasyTier are explicitly unavailable.
Gateway configuration/recovery and CSV import/export remain real backend calls.

The interaction-only changes were applied to Overview, Processes and Traffic
before preparing any visual drafts. The integration owner passed the isolated
Qt 6.12 build, 61-route startup smoke and 68 native interaction checks with no
QML warnings before authorizing these six visual sources to be applied. This
is shared controlled application evidence; it is not a six-page data-specific
or private-network acceptance claim. The other three pages retain their
existing validated interaction components.

## Visual composition

All pages consume the shared near-white/navy/cyan Theme, current fontManager
and stable SwirlPageHeader API. Overview uses grouped capability rows instead
of repeated cards. Processes, Connections and Logs use an open toolbar, a
single table and a responsive source-linked inspector. Gateway replaces its
absolute-positioned columns with a responsive Layout, preserves settings and
recovery/CSV commands, and gives empty/error states actual meaning.
At narrow widths the inspectors stack below the table; unused process/device/
log inspectors leave the table room to grow. Detail content remains scrollable
at compact heights. Dynamic names and diagnostic text render literally.

Traffic distinguishes selected-period accounting from live rates. Three hero
metrics form a measuring band; four period statistics are unboxed, followed by
the existing real one-hour rate chart and sampled rankings. Missing samples
remain unavailable values and empty states. No illustrative rows or progress
were added. Existing retention and connection-attribution limits remain clear.

Static audits compare original objectNames/backend action coverage, all route
metadata (including revision/generation), metric anchor IDs and the four
LinkedDetail source/target contracts. They are source checks, not compilation
or native acceptance. The integration owner runs qmlcachegen/build, smoke,
native interactions and screenshots. No standalone build or GUI was launched.
The six visual files are now applied and frozen. They add no QML file or CMake
registration. Source audit and git diff --check pass; final-source compilation,
native repetition and screenshot review remain pending integration.

References: the existing APEC motion foundation and Qt 6.12 implementation
sources already recorded in APEC_MOTION_FOUNDATION.md; retained Swirl native
table/transfer controls. No third-party implementation was copied. Host proxy,
TUN, routes, DNS, user data and private subscriptions were not accessed or
changed by this migration.
