### A separate native failure was an interpreter budget, not geometry fitting

Earlier shared Horner candidates passed CoreText but truncated in unmodified
HarfBuzz: **32 / 247 topology failures** across 6,514 / 6,949 requests. In the
first 19177 failure, the decoded program needs 394,895 executed tokens.
Token 200,000 falls after exactly 11 contour moves and 66 curves, matching the
native truncated prefix. Another program needs 328,565 tokens and truncates
after 12 moves and 69 curves. HarfBuzz counts numeric operands and expanded
subroutine execution, so sharing file bytes alone cannot fix this limit.
See the pinned [HarfBuzz 14.6.0 limits](https://github.com/harfbuzz/harfbuzz/blob/c7a7457b7385f33178e8cf87615ca077a810bbe7/src/hb-limits.hh)
and [CFF interpreter loop](https://github.com/harfbuzz/harfbuzz/blob/c7a7457b7385f33178e8cf87615ca077a810bbe7/src/hb-cff-interp-cs-common.hh).
No engine limit was changed and no custom native engine was substituted.

The correction has three parts:

1. Round coefficients to the actual CFF2 16.16 representation before pruning
   zero Horner branches. Positive and negative ramp operands round separately,
   preserving half-tick asymmetry.
2. Bound each nonnegative sparse tensor hat over the entire patch, padded by
   two F2DOT14 ticks. Signed interval accumulation includes a floating-point
   error margin. A ramp is removed only when this bound proves its stored avar2
   output saturates throughout that box. Its separately rounded signed
   polynomial is then included in the baseline. Uncertain ramps remain variable.
   Validation positions are never used to certify or remove a ramp.
3. Count expanded interpreter tokens, including helper/chunk calls and implicit
   returns, for every emitted glyph. Reject the shared compiler output if any
   program reaches the tested engine's 200,000-token budget. Byte length, call
   depth, operand stack and region capacity retain their separate guards.

The interval proof preserves the quantized polynomial represented at a saturated
endpoint. Native floating-point evaluation can reorder arithmetic, so real
serialized acceptance remains mandatory. This is not a bit-identical-output
claim for every engine or a bound on the whole fitted source function.

## Sparse clamp maps and source-aware component partitions

`sparse_projection` fits the **unclamped** rational projection parameter with
hierarchical tensor hats. It takes mixed hierarchical differences using cached
parents; it does not solve a dense tensor system. For M ramps, the exact scalar
identity is `clamp(t,0,1) = sum(clip(2*M*t-(2*j+1),-1,1)+1)/(2*M)`.
The compiler quantizes avar2 deltas first, then removes only exact zero rows.
Physical output-axis deltas stay zero. Region coordinates, delta capacity,
training-node budget and hidden-axis counts have explicit format guards.

`adaptive_projection_atlas` fits baseline/direction fields, retaining source
axis-zero and Type-0 branches. Analytic branch intersections propose cut planes;
measured field bends choose among them. Midpoint cuts remain an explicit
reproduction option. Both modes test source branch intersections and nearby
positions in refinement, independently of held-out acceptance. Every source
evaluation used for fitting/refinement receives a location fingerprint, saved
with the private atlas and bound to source SHA/face/GID. Holdouts overlapping
these receipts or each other are rejected. No native result enters the fitter.

Nine authored regression tests cover sparse mixed-axis fields, OpenType scalar
agreement, clamp quantization, capacity failures, source-derived cut positions,
all octants, source identity and training/holdout separation. The source-aware
cut heuristic is still being evaluated on real glyphs; these tests do not
certify its resource cost or arbitrary-space precision on the complete font.
