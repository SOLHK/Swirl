# Swirl U2 (2026-10-23)

Base: 2a4891ca758dfc55f62ad7e78ce692ddd25f491d, the current 0.1.3 window/UI branch. Work is isolated on work/ui-window-node-performance-20261023. Other worktrees and their uncommitted changes are preserved.

## References and implementation boundaries

- Qt's upstream view examples: https://github.com/qt/qtdeclarative/tree/dev/examples/quick/views
- Qt ListView reuse and model lifecycle: https://doc.qt.io/qt-6/qml-qtquick-listview.html
- Rust OpenHarmony compilation guidance: https://doc.rust-lang.org/stable/rustc/platform-support/openharmony.html
- HarmonyOS VPN API/permission qualification is separate from Rust target compilation: https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/net-vpnextension

Independent implementation using the existing Qt components. No external proxy core is added. Protocols, subscription parsing, DNS, routing and probing belong to portable Rust; native window/system proxy/TUN/permission code belongs to adapters. OpenHarmony compiler support is not evidence of HarmonyOS NEXT VPN entitlement or device acceptance. No Android VPN API is assumed for HarmonyOS NEXT.

## U2-A

The existing activity default is 914 x 672 logical units at 100% application scale; minimum 760 x 672. There was no reproduced route-induced top-level resize in this baseline. The reproduced visible change was the sidebar: activity 168 versus all other routes 208. The shared width is now 168. Default window geometry is owned by Theme/Main, and the secondary panel shares the default. Manual resizing and saved normal geometry remain intact. Settings already uses responsive grids and scrolling; node content is addressed in U2-C.

Release Rust/Qt Windows build passed with Qt 6.10.3/MinGW. Native Qt test at actual DPR 1.5 checks every implemented route, manual resize retention, then 100 animated switches. Baseline: 63 sidebar failures, zero other failures. U2-A: zero failures. Exact reports are in evidence/ui-u2. No claim of real proxy/TUN/network acceptance follows from these UI results.

Reproduce with the UI-test build: set SWIRL_U2_CHECKS=A and run Swirl --motion-test --motion-output=report.json. Test storage is isolated. SWIRL_U2_SOAK_SECONDS optionally extends the activity idle scenario. Process-local Qt scale factors do not change Windows display settings.

## U2-B

WindowCornerRadius and SidebarCornerRadius are both 14 Qt logical units, independent of devicePixelRatio and manual content zoom. Existing four-corner framebuffer alpha clipping and the matching perimeter shadow remain in the Windows adapter; no extra full-window texture/mask is introduced. Native composition diagnostics no longer claim an obsolete 10pt radius.

Rust/Qt Release build passed. Five native Qt runs at effective DPR 1, 1.25, 1.5, 1.75 and 2 each passed all geometry/sidebar/radius/100-switch assertions. The host display itself stayed at 150%; per-process QT_SCALE_FACTOR supplied the other effective DPRs. Actual Windows Settings DPI changes and cross-monitor drag remain unverified. This is not a claim of macOS UI acceptance. Native image at DPR 1 was inspected; all five rendered captures remain in the local evidence directory.
