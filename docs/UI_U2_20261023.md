# Swirl U2 (2026-10-23)

Base: 2a4891ca758dfc55f62ad7e78ce692ddd25f491d, the current 0.1.3 window/UI branch. Work is isolated on work/ui-window-node-performance-20261023. Other worktrees and their uncommitted changes are preserved.

## References and implementation boundaries

- Qt's upstream view examples: https://github.com/qt/qtdeclarative/tree/dev/examples/quick/views
- Qt ListView reuse and model lifecycle: https://doc.qt.io/qt-6/qml-qtquick-listview.html
- Rust OpenHarmony compilation guidance: https://doc.rust-lang.org/stable/rustc/platform-support/openharmony.html
- HarmonyOS VPN API/permission qualification is separate from Rust target compilation: https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/net-vpnextension

Independent implementation using the existing Qt components. No external proxy core is added. Protocols, subscription parsing, DNS, routing and probing belong to portable Rust; native window/system proxy/TUN/permission code belongs to adapters. OpenHarmony compiler support is not evidence of HarmonyOS NEXT VPN entitlement or device acceptance. No Android VPN API is assumed for HarmonyOS NEXT.

## U2-A

The existing activity default is 914 x 672 logical units at 100% application scale; minimum 760 x 672. There was no reproduced route-induced top-level resize in this baseline. The reproduced visible change was the sidebar: activity 168 versus all other routes 208. The shared width is now 168. Default window geometry is owned by Theme/Main, and the secondary panel shares the default. Manual resizing and saved normal geometry remain intact. Settings already uses responsive grids and scrolling; node content is addressed in U2-C.

Release Rust/Qt Windows build passed with Qt 6.10.3/MinGW. Native Qt test at actual DPR 1.5 checks every implemented route, manual resize retention, then 100 animated switches. Baseline: 63 sidebar failures, zero other failures. U2-A: zero failures. Exact reports are in evidence/ui-u2. No claim of real proxy/TUN/network acceptance follows from these UI results.

Reproduce with the UI-test build: set SWIRL_U2_CHECKS=A and run Swirl --motion-test --motion-output=report.json. Test storage is isolated. SWIRL_U2_SOAK_SECONDS optionally extends the activity idle scenario. Process-local Qt scale factors do not change Windows display settings.

## U2-C

Node browsing uses QAbstractListModel/QSortFilterProxyModel with stable IDs and per-row dataChanged, ListView recycling, 100ms search debounce, name/protocol/host/region-hint search, combined source/protocol/status/latency filters, sorting, favorites and up to 32 verified recent connections. Preferences are separate from the encrypted node format. Subscription-owned nodes cannot be edited/deleted from this UI. The detail copy action has an explicit public-field allowlist. Existing name-based regions are labelled hints, not verified geolocation. Session readiness is separate from successful target-request evidence.

The full-width list opens a complete content-area detail view. At the default geometry, identity/actions and request settings occupy two columns; narrow layouts scroll under a fixed return header. The user-reported empty transition and gray corner blocks were reproduced: an independent blank ScrollView background and delayed body opacity exposed an empty panel; a rectangular scrim covered rounded page corners. Removed the empty background/delayed text reveal, made target layout independent of reveal progress, and matched the scrim radius. Four pixel comparisons verify the outside-corner background remains unchanged. Deleting the selected node closes the detail surface.

Windows Qt native checks: 419 nodes rendered 17 delegates; 5000 nodes rendered 33; load plus a deliberate 100ms settling interval was 102ms/133ms. C++ model tests: 3 passes, 30 search edits on 5000 rows took 81ms, no source model resets, one changed row caused one row notification. Actual controlled loopback SOCKS/HTTP/HTTPS-subscription UI chain: 348 checks, zero failures using Qt offscreen/software. This verifies real fixture traffic and storage behavior, not private provider reachability or native compositor quality. Native detail and corner checks separately passed. Failed intermediate UI runs are not counted as passes.

## U2-D

Navigation records detail depth separately from browser-style history. Activity drill-downs explicitly enter a detail level, including routes also available in the primary sidebar. Escape is owned by the window dismissal controller: cancel input-method composition first, dismiss the top registered menu/dialog, then close an internal node detail, then return one route level. Primary pages remain open. Combo menus and context menus register their own dismissal layer. Back buttons share the route history, retaining animations and cached pages.

Native Qt keyboard tests passed: primary Escape, six activity destinations, two nested returns, dropdown-before-page priority, text-field focus and unchanged geometry. The controlled UI suite also checks cancelling a destructive subscription dialog. A real Chinese IME composition session and native OS file-dialog interactions remain unverified; the composition guard is implemented but not claimed as physical IME acceptance.

## U2-E (implementation gates; sustained/native acceptance still in progress)

Node updates are coalesced for 50ms and unchanged snapshots do not notify the proxy model. Engine polling no longer emits nodesChanged for unchanged presentation. Node test runners use ThreadedEngine, carrying immutable probe metadata in queued status snapshots so Rust setup/probing does not block the UI thread. The three-runner limit is unchanged. Navigation history is bounded at 128, and page-cache trimming avoids copying maps when already within capacity; animations and cached page interactions remain enabled.

Rust platform-specific host-file discovery moved to swirl-platform. Shared DNS consumes the adapter API; mobile targets do not guess a desktop host path. A dependency/source boundary check and dedicated CI cover Windows/Linux/macOS and full iOS/Android core compilation. OpenHarmony CI only compiles the subscription and platform modules: full SDK/network integration and VPN permissions remain unverified.

Local gates: Rust fmt/check/strict clippy and 361 tests passed; portable boundary 2 tests passed; subscription and platform crates compile for Linux/macOS/iOS/Android/OpenHarmony. Updated Qt model tests passed, with 30 searches over 5000 rows in 98ms (not claimed as an improvement over the earlier 81ms). Controlled real loopback UI chain: 348 checks, zero failures. Rust/Qt checks: 72 passes and 9 explicit skips; skipped independent/private protocol fixtures are not acceptance. Native 100-route-switch/node stress check passed; worst sampled event-loop gap was 109ms under concurrent local verification. No 60 FPS guarantee or percentage CPU/RAM reduction is claimed. Thirty-minute final-build soak and CI results will be appended when available. Interrupted soak runs do not count as passes. Current corner appearance is still being revised against the user's Apple image reference.

## Final image-reference corner revision (0.1.4)

The user's latest Apple Music images supersede the earlier 14/14, 12/16 and 10/16 numeric requests. The supplied 1920x1280 reference has an approximately 1078px-high outer window. Threshold sensitivity measurements of its top-left outer contour favor a 2.5-power corner with an extent of about 37-38px; the sidebar inner bottom-left extent is approximately 26px. At Swirl's existing 672-unit default height these correspond to approximately 24 and 16 logical units. This is an independently fitted image contour, not a claim about Apple's undocumented native point values or a lossless pixel identity with a compressed/rescaled screenshot.

The outer alpha edge, Windows coverage region, perimeter shadow, vector rim, sidebar shadow and sidebar rim now use that same curve family. The rim is one physical pixel at each DPR. Only the perimeter is drawn; text is not resampled through a full-window texture. Secondary windows share the shell contour. Maximized/fullscreen windows retain rectangular edges. Version is 0.1.4.

Native compositor captures at effective DPR 1, 1.25, 1.5, 1.75 and 2 completed. The 1.5 capture was visually inspected against the reference, including outer and sidebar corners. Final native 100-switch/419/5000-node run: zero failures, maximum sampled event-loop gap 31ms. Detail reveal/minimum-size scrolling/four-corner scrim and layered Escape checks passed again. The screenshots are local desktop evidence, not public repository assets. The host OS remained at 150%; actual display-setting changes/cross-monitor drag remain unverified.

## User acceptance handoff and compositor-edge correction (0.1.5)

The user took ownership of stutter/interaction testing. Automated page-switch pressure testing and the visible idle-preview soak were stopped. No 1000-switch run was performed. The final 0.1.4 soak reached approximately 390 seconds before deliberate handoff; it is not a 30-minute pass. The pre-E test build did complete 1801 seconds, but its warm scene/build cannot be compared directly with the final product's cold scene. Smoothness and long-running final-product acceptance remain with the user; automated results do not establish subjective responsiveness.

The subsequent user photo rejected 0.1.4's outer-edge quality. Native compositor magnification reproduced a stepped fringe even though the Qt framebuffer had fractional alpha. The GPU main HWND no longer applies a binary HRGN over the final alpha edge. The live-blur helper no longer adds a second thick-frame/preset-corner boundary; its HWND itself is inset within the superellipse because Accent blur can ignore its HRGN. The inset is the measured diagonal cut plus one physical pixel, preserving live blur in the covered interior. The separate perimeter shadow now has fractional edge coverage. The corner shader integrates its local edge across a square physical pixel instead of using a fixed normal-distance smoothstep. This is perimeter antialiasing, not whole-window blur or text resampling. The reference curve extents and sidebar geometry are unchanged.

Static native captures at effective DPR 1/1.25/1.5/1.75/2 completed; magnified compositor comparisons were inspected. An intermediate attempt still leaked a rectangular blur corner and was rejected before delivery. Hardware rendering is the validated path; the software renderer retains its binary-region fallback and is not claimed to have the same antialiasing quality. Actual OS scale changes/cross-monitor behavior remain unverified.

A separate non-UI regression exercised real loopback SOCKS/HTTP traffic: six peer rejections, recovery across 24 queued probes, cancellation, reuse and runner destruction. Passed with no compatibility fallback and a maximum of three live runners. This validates function/lifecycle, not UI smoothness. The initial test used invalid synthetic IDs, failed validation, and was corrected to valid UUIDs before the passing run.
