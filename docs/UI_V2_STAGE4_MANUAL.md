# Swirl 0.2.5 策略页人工验收

本版为阶段 4 诊断版。受控对端验证不能证明私人供应商节点或 Codex 服务已可用；安装包、最终提交和自动测试结果请同时查看交付报告。安装前退出同目录的 Swirl，保留原配置备份。不要同时让两个 Swirl 实例写同一配置库。已有工作代理、TUN、DNS和路由由你自行决定是否切换。

## 默认策略与模式

1. 打开“策略”。已有旧配置时先检查迁移预览，确认原选中节点、组引用、规则顺序及提示的行为差异，再确认迁移；未确认前不应静默改写旧配置。
2. 在“服务分配”顶部为“默认策略”选择一个已验证节点或策略组。默认策略不能删除，也不能选 DIRECT/REJECT。没有可用出口时保持未配置，不能自动选择第一项。
3. 未连接时保存，状态应显示“已保存，下次连接生效”。连接后查看实际应用状态。在线修改默认出口后，等待“已生效”再发起新请求；保存失败时编辑内容应留在表单中。
4. 分别检查“规则分流”“全局代理”“直连模式”。规则分流按本地/明确直连、专属服务、国内分类、自定义规则、默认策略的顺序处理。全局代理仍保留必要本地例外；直连模式不使用代理出口。

## 专属服务与规则

1. “添加策略”中填写名称、域名、出口和优先级。可添加多条精确域名或包含子域名规则；多条之间为 OR。包含 `example.com` 不应捕获 `notexample.com`。
2. 分别为 OpenAI/ChatGPT、Claude、Google、YouTube 创建明确的域名集合，选择你实际希望使用的出口。名称只是标签，不会自动生成网站列表；不要只改名称就认为已经识别该服务。
3. Google/YouTube 及共享登录/CDN 的归属要明确配置。系统代理无法通过 HTTPS 目标域名判断共享登录属于哪个网页，也不会解密网页。需要同一登录出口时，显式选择同一具体节点或固定手动路径。
4. 重叠时检查冲突提示中的策略、优先级和实际胜者；修改优先级后再次保存。停用某服务后，其新请求应回到下一匹配层或默认策略。
5. 点击“查看规则”，在“规则”页检查明确的节点或组出口；不能因原目标删除而默默变为 DIRECT。应用程序和应用+网站组合当前不可用，TUN 也不可用。

## 策略组

1. 切到“策略组”，依次新建手动选择、自动测速、故障转移和负载均衡组。组名可以修改，引用身份不应变化。
2. 手动组明确选择成员。嵌套组可以作为候选；循环、超深或超预算图必须拒绝，失败草稿不能改变已保存配置。
3. 展开“健康检测和自动切换”，检查探测地址、间隔、超时、状态码、成功/失败阈值、冷却和容差。自动组需要真实健康结果；未知或过期结果不能当作可用，更不能自动改直连。
4. 负载均衡以服务身份保持新连接出口粘性；重命名不应随机换出口。不同服务仍可获得不同节点，不能把相同组等同于相同出口。已建立连接保持原路径，明确删除来源/节点属于撤销例外。
5. 在最小窗口、键盘 Tab 和 Esc 下检查表单。只修改成员也应触发放弃草稿确认；提交进行中不应被 Esc 关闭。高 DPI、多显示器和实际手感需在你的设备上检查。

## 实际出口与删除

1. 先确认所用节点本身可访问目标，再经 Swirl 显式代理发起新请求。在连接详情核对模式、命中层/规则、服务、策略组链、最终节点、选定 IP、DNS 路径和配置版本；仅有监听端口、绿色状态或测速数值不等于联网成功。
2. 选两个可辨认出口 A/B：默认设 B，专属服务设 A。检查普通海外请求走 B、专属请求走 A、本地必要流量直连；国内规则的判断还须结合实际目标与解析证据。
3. 浏览节点资源库、收藏或单独测 B 不应改变正在使用的 A。策略页明确修改出口后，新请求才应变化。
4. 删除来源/节点后，受影响的新旧连接应撤销，其他来源保持运行。被引用的删除目标应显示不可用，不得自动改成另一节点或 DIRECT。共享单个 JSON 出站的多账户暂拒绝部分删除，可删除整个来源或按独立出站重新导入。
5. 若提示待恢复，先恢复并确认状态再连接。恢复期间旧来源下载和独立节点测速应被阻止，不能用反复重试绕过恢复。

自动订阅刷新只更新节点，不自动覆盖 DNS、规则和策略组。完整订阅页与一次性配置预览仍在下一阶段；窗口和侧栏统一 14dp 在阶段 6。普通明文 HTTP 每个连接只处理一次请求并关闭；CONNECT/已确认升级的 WebSocket 保持隧道语义。

失败时先截取策略状态、连接详情和错误出现时刻，再到“日志”点击“导出诊断报告”。也可到“设置”的“本地连接诊断”点击“开始诊断”，完成后“保存诊断报告”。

请记录成功、失败、跳过和未验证项目，附目标类型、实际出口、错误码和出现时机。分享诊断前确认没有订阅地址、账号、口令、私人节点或解密原文。
