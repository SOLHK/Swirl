# HTTP 捕获、HTTPS 解密与重写

“捕获”页设置限时、大小、请求数及过滤器，启用后监听本机 HTTP 代理端口。在“面板 → 最近的请求”查看记录，点击请求检查内容并导出 HAR。

客户端必须使用捕获端口作为 HTTP/HTTPS 代理。如果 Swirl 已接管 Windows 系统代理，启停捕获会切换 Swirl 自己拥有的代理端口；未接管时不会修改系统代理。独立程序可显式设置 127.0.0.1:捕获端口。这不是全网卡 PCAP。

## HTTPS

“解密”页可生成 RSA CA、导入密码保护的 RSA PKCS #12 CA、导出公开证书，并由用户点击安装到当前用户 Windows 信任存储。私钥使用 DPAPI 加密保存；生成或导入 CA 不会自动安装信任。

添加 MitM 主机名，支持通配符和 -private.example.com 排除项。排除项优先。没有命中的 CONNECT 保持不透明隧道。捕获页的“自动开启 MITM”在捕获时使用已配置 CA 和主机名，独立于解密主开关。

支持 HTTP/1.1 与基于 nghttp2 的 HTTP/2 客户端解密，包括同一 TLS 连接的多个流。MitM over HTTP/2 控制 ALPN 协商。默认验证上游证书；跳过验证必须手动选择。自动屏蔽 QUIC 尚未实现，对应控件禁用。证书固定的客户端可能拒绝本地 CA。

## 重写与映射

支持 URL 重定向、Header 重写、Mock 静态响应、Body 重写、本地 TCP 端口转发。规则校验并持久化。HTTP 规则只处理经过捕获端口的请求；HTTPS 规则还需要成功解密。

## 限制

- 64 个活动连接、1000 条内存历史；HTTP/2 每连接最多 32 个流。
- 请求正文上限 1 MiB；大响应可流式转发，正文预览/HAR 最多保留 64 KiB。Body 重写仍要求响应不超过 2 MiB。
- 不支持分块请求上传、HTTP Upgrade、完整断点暂停/编辑或 HTTP/3 解密。
- HTTP 字节统计为正文载荷；不透明 CONNECT 为隧道载荷。捕获数量和大小限制独立于过滤器及清空历史。
- 认证、Cookie 和常见 URL 密钥在记录中隐藏，正文可能包含用户数据。记录只在进程内存中，除非主动导出。

## 验证

测试构建启用 SWIRL_BUILD_UI_TESTS=ON，运行 Swirl.exe --capture-self-test。使用本机 HTTP/TLS 服务验证真实转发、HTTP/2 多流、3 MiB 响应、CA 及 PKCS #12、主机名范围、重写、HAR、限制和关闭监听。不安装系统信任，不修改系统网络配置。生产构建不包含测试入口。
